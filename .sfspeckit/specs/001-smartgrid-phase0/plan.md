## 1. Technical Architecture

### 1.1 Apex Architecture
Adhering to our separation of concerns, the backend strictly splits structural schema parsing from UI orchestration.

1. **`GridQueryBuilder.cls`** (Selector/Domain Layer)
   - *Methods*: `buildQuery(objectApiName, fields, filterField...)`, `validateFields()`, `isValidFilterField()`.
   - *Role*: Constructs safe dynamic SOQL strings. Runs the Schema Describe calls to fetch FLS properties. Annotated with `@InvocableMethod` to support future AI interactions.
   - *Security*: MUST handle namespaces correctly (e.g. `Apttus__`). Avoids direct SOQL execution, strictly returns safe strings.

2. **`SmartGridController.cls`** (Service/Controller Layer)
   - *Methods*: `@AuraEnabled getGridConfig()`, `getObjectFields()`, `getRecords()`, `saveRecords()`.
   - *Role*: Thin LWC wrapper. Executes queries dynamically generated by `GridQueryBuilder` using `WITH USER_MODE`. Handles the `Database.update(records, false)` and manages the wrapper object structure sent back to JS via custom types (`SaveResult`, `ColumnInfo`).

### 1.2 LWC Architecture
1. **`smartDataGrid`** (Parent)
   - *Role*: Evaluates the inputs (`gridConfigName` vs `objectApiName`), fetches config, renders `lightning-datatable`, handles edit states (`defaultMode`), handles save row actions.
   - *Targets*: AppPage, HomePage, RecordPage. (Specifically NOT Screen Flow or Community per clarifications).

2. **`smartGridFieldPicker`** (Child)
   - *Role*: Renders a modal over the grid with a `lightning-dual-listbox` to select field views if no setup exists (Auto-discovery mode). Fires custom event `<fieldselection>` back to parent.

### 1.3 Target Package
Objects, Classes, and LWCs will exist under `force-app/main/default/`.
